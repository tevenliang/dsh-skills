# 面试专家 (Interview Expert)

> **Skill 定位**:帮用户搞定求职面试的**全流程**——出题、改简历、模拟面试、复盘。
> 未来会扩展:更深入的简历诊断、面试能力训练、行业知识图谱等。

## 快速开始

**大多数情况下无需任何配置,直接使用:**

| 文件类型 | 是否需要配置 Token |
|---------|-----------------|
| 文本版 PDF(可复制文字)| ❌ 直接使用 |
| Word 文档(.docx / .doc)| ❌ 直接使用 |
| TXT 纯文本 | ❌ 直接使用 |
| 直接粘贴文字 | ❌ 直接使用 |
| 图片(JPG / PNG / WEBP)| ✅ 需要 Token |
| 扫描版 PDF(无法复制文字)| ✅ 需要 Token |

---

## 配置 PaddleOCR Token(仅图片/扫描版 PDF 需要)

1. 访问 https://aistudio.baidu.com/paddleocr
2. 右上角获取 Access Token
3. 编辑 `~/.hermes/skills/productivity/interview-expert/.env`,填入:
   ```
   PADDLEOCR_TOKEN=你的token
   ```
4. 或设置系统环境变量:`export PADDLEOCR_TOKEN=你的token`

## 第一步:解析文件

对简历和 JD 文件,分别执行:

```bash
/usr/bin/python3 ~/.hermes/skills/productivity/interview-expert/scripts/parse_input.py "<文件完整路径>"
```

**支持格式:** `.pdf` `.docx` `.doc` `.txt` `.jpg` `.jpeg` `.png` `.webp`

如果用户直接粘贴了文字内容,跳过此步骤。

解析失败或输出为空时,告知用户具体错误信息,并请他直接粘贴文字内容。

**Windows 用户** 请改用以下命令避免乱码:
```bash
set PYTHONIOENCODING=utf-8 && python %USERPROFILE%\.claude\skills\interview-expert\scripts\parse_input.py "<完整路径>"
```

## 第二步:选择模式

根据用户意图,选择以下**四种模式之一**:

### 模式 A:出题模式(考点分析 + 面试题生成)

触发词:「帮我准备面试」「根据JD出题」「给我出几道面试题」

**分析维度:**
- **技能匹配**:JD 要求的每项技能 → 简历中是否有对应经历(有→深挖,无→补考)
- **项目挖掘**:简历中的重要经历 → 设计 STAR 追问(背景/任务/行动/结果)
- **行为面试**:JD 软技能要求 → 结合候选人背景出具体事例题
- **情景假设**:岗位核心职责 → 设计真实工作场景题
- **动机匹配**:离职原因、选择理由、职业规划

**出题要求:**
- 共 14–18 道题,优先质量而非数量
- 同一技能点不超过 2 道题
- 语言跟随 JD(中文 JD 出中文题)
- 每道题格式:

```
【题目 N】
分类:技术硬技能 / 项目经历 / 行为面试 / 情景假设 / 动机匹配
难度:易 / 中 / 难
出题依据:(一句话,关联到 JD 或简历的具体点)

题目:……

答题要点:
1. ……
2. ……
3. ……

参考答案:……(100-200字)

⚠️ 红线提示:……(什么样的回答说明有问题)
```

**出题技巧**详见 [`references/question-types.md`](references/question-types.md)

---

### 模式 B:简历优化模式(根据 JD 改简历)

触发词:「帮我改简历」「优化简历」「简历怎么针对这个JD修改」

需要同时拥有简历和 JD 才能执行(解析方式同第一步)。若只有简历,先输出通用优化建议,再提示提供 JD 可做针对性修改。

#### 分析框架

对简历和 JD 做三层比对:

1. **关键词覆盖**:JD 高频词、硬技能词是否出现在简历中(影响 ATS 系统过滤)
2. **经历相关性**:现有经历哪些与 JD 强相关、哪些可以弱化或删除
3. **表达方式**:描述是否量化、是否突出个人贡献、是否契合岗位语言风格

#### 输出格式

先输出一段总体评估(3–5 句),说明简历与 JD 的整体匹配度和核心差距,再逐条给出修改建议。

每条修改建议格式:

```
【修改项 N】优先级:高 / 中 / 低
位置:(简历中的具体模块,如"工作经历·XX公司·第二条")
问题:(一句话说明当前写法的不足)
修改原因:(关联到 JD 的具体要求,说清楚为什么这么改)

原文:
……

建议改为:
……

改动说明:
- ……(每处改动对应一条说明,解释改了什么、为什么)
```

#### 修改原则

- **只增强,不捏造**:所有修改必须基于用户已有经历,禁止添加简历中未提及的项目、技能或数字
- **量化优先**:能加数字的地方优先补充,没有数据时引导用户回忆("这个项目大概影响了多少用户/节省了多少时间?")
- **关键词自然植入**:将 JD 核心词融入描述,但不得堆砌关键词到影响可读性
- **删减也是优化**:与 JD 关联度低的经历建议缩减篇幅,而非一律保留
- **语言风格对齐**:互联网公司 JD 倾向结果导向,咨询/金融 JD 倾向逻辑严密,外资倾向英文术语

**修改技巧**详见 [`references/resume-optimization.md`](references/resume-optimization.md)

#### 结尾引导

修改建议输出完毕后,主动询问:
> "以上是针对这份 JD 的简历修改建议。需要我帮你把修改后的完整简历重新整理成一份吗?或者有哪条修改你想进一步讨论?"

### 模式 C:模拟面试模式(对话演练)

触发词:「模拟面试」「面试演练」「你当面试官问我」

**执行流程:**
1. 根据用户的简历 + JD,先确定面试官画像(行业、公司风格、面试轮次)
2. 自我介绍:
   - 告诉用户:"我将以[公司] [岗位] 资深面试官身份提问,共 6-8 轮。开始前请确认你了解:[1] 面试官会基于你的简历追问,不会超纲 [2] 答题后我会给反馈 [3] 任何时候可喊停复盘"
3. 一轮一轮地:
   - 先出题(简短、清晰,跟真面试一样)
   - 等用户回答
   - 给出**结构化反馈**:✅ 好的点 / ⚠️ 模糊的地方 / 💡 改进建议
4. 全部结束后做一次**整体复盘**(模式 D 的内容)

**模拟面试的反馈原则:**
- **先肯定再说不足**:哪怕回答很烂,也先指出"思考方向对/有具体例子"等亮点
- **具体而非泛泛**:不要只说"不够详细",要说"这里可以补一个数字,比如影响了多少用户"
- **基于岗位标准**:互联网重结果导向,咨询重逻辑,技术重原理深度

---

### 模式 D:复盘分析模式(面试后总结)

触发词:「帮我复盘」「面试完了,总结一下」「刚才答得怎么样」

**适用场景:** 用户刚面试完,口述/粘贴面试过程,需要专业反馈

**执行流程:**
1. 收集信息:面试的公司、岗位、轮次、关键问题、用户回答(可贴聊天记录)
2. 逐题分析:
   - 问题理解:面试官到底在问什么?(考察什么能力/信号)
   - 回答评估:✅ 好的 / ⚠️ 扣分的 / 💡 改进版
3. 整体评分(满分 10):
   - 内容匹配度(40%):跟 JD 要求的契合程度
   - 表达清晰度(20%):逻辑结构、用词
   - 自信度(20%):语气、节奏、有无废话
   - 印象分(20%):开场结尾、互动感
4. 给出 3-5 条**最该改进**的事项(按优先级排)
5. 如果是同一公司后续轮次:基于这次表现预测下一轮可能问的方向

## 边界情况

**模式 A(出题):**
- 只有简历没有 JD:出通用题,提示"提供 JD 后可出更精准的题目"
- 只有 JD 没有简历:出岗位标准题,提示"提供简历后可针对经历定制"

**模式 B(简历优化):**
- 只有简历没有 JD:给出通用优化建议(量化、动词开头、去冗余),提示"提供 JD 后可做针对性修改"
- 只有 JD 没有简历:提示需要简历才能开始,无法凭空生成

**模式 C(模拟面试):**
- 用户中途说"换岗位":先复盘当前轮次,再切换设置
- 用户卡住不知道答什么:给 30 秒提示(给一个思考方向/示例),不要直接给答案

**模式 D(复盘):**
- 用户没给具体问答:引导用户回忆或描述大概内容
- 用户没参加面试:跳到"基于简历+JD 做预测性分析"——可能面试官会问什么

**通用:**
- 文件解析失败:告知用户具体错误,提示直接粘贴文字内容
- 用户同时要求多个模式:按 A→B→C→D 顺序串联输出,中间用分隔线区分
