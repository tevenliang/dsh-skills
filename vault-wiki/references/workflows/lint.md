# Lint — 健康检查（vault 版）

核心理念：随着 wiki 增长，定期体检保持知识库健康。LLM 不仅发现问题，还主动建议值得探索的新问题和新源。

## 前置条件

- 已 Read AGENTS.md 查看规范（`Read` `wiki/AGENTS.md` 或根目录 `AGENTS.md`）

> **命令约定**：本工作流所有读取用 `Read` 工具读 `.md` 文件；所有修复用 Read → 改写 → Write 回写。INDEX.md 注册表/配置的写回遵循 [wiki-schema.md](../wiki-schema.md)「索引操作规则」（整篇重写首选，局部替换备选）。

## 检查维度

以下 10 项维度**每次 lint 都必须全部检查**：

| # | 维度 | 说明 | 检查时机 | 严重级别 |
|---|------|------|---------|---------|
| D1 | 空白页面 | 仅有标题或元数据 frontmatter、缺少实质内容 | 全量读 | ERROR |
| D2 | 引用格式与断链 | `[[...]]` 指向不存在的文件，或仍残留飞书 `<cite>`/`<mention-doc>` | 全量读 | ERROR |
| D3 | 未索引页面 | wiki/ 子目录中实际存在但未在 INDEX.md 注册表中登记的页面 | 目录扫描 | ERROR |
| D4 | 重复页面 | 标题或内容高度相似的页面，应合并 | INDEX + 全量读 | WARNING |
| D5 | 孤立页面 | 无入链的页面，缺乏知识网络连接 | INDEX | WARNING |
| D6 | 矛盾检测 | 不同页面间的事实冲突 | 内容深度检查 | WARNING |
| D7 | 过时声明 | 新源已取代旧页面中的论述 | 内容深度检查 | WARNING |
| D8 | 交叉引用缺失 | 应当互相引用但未链接的页面 | 全量读 | INFO |
| D9 | 缺失页面 | 被多次提及但尚未创建独立页面的重要概念/实体 | INDEX + 全量读 | SUGGESTION |
| D10 | 源文档更新 | raw/ 原始文档在 Source 页 updated 后被修改过 | 脚本检查 | WARNING |

## 步骤

1. **从 `~/.llm_wiki.setting.json` 读取配置**（含 wiki 根路径），Read INDEX.md → 解析注册表
   ```bash
   # 直接用 Read 工具读 wiki/INDEX.md
   ```

2. **目录扫描**（对比 INDEX.md 注册表与 wiki/ 子目录的实际内容）
   - **[D3 未索引页面]** 逐个扫描 wiki/sources、wiki/entities、wiki/concepts、wiki/comparisons、wiki/overviews 五个子目录：用 `ls` / `find` 获取每个子目录的实际文件列表
   - 将实际文件列表与 INDEX.md 注册表对比，找出存在于目录中但未在注册表中登记的页面 → 应补充索引或删除

3. **INDEX 级检查**（仅从注册表即可判断，无需读页面）
   - **[D5 孤立页面]** 扫描所有页面的「关联」列，找出无入链的页面
   - **[D4 重复页面-标题级]** 检查注册表中标题相似的条目（如同名 Entity/Concept、中英文同义词、去掉前缀后相同），记录疑似重复组
   - **[D9 缺失页面-初筛]** 扫描所有页面「关联」列中引用的路径，找出未在注册表中注册的条目

4. **全量读检查**（逐页 Read 所有注册页面，确保无遗漏）
   - **[D1 空白页面]** 检查页面内容：如果仅有标题、或仅有 YAML frontmatter 而无实质段落内容 → 标记为空白页
   - **[D4 重复页面-内容级]** 对步骤 3 标题相似的疑似重复组，读后对比内容确认是否为真正重复
   - **[D2 引用格式与断链]** 提取页面内所有 `[[...]]` 引用，检查目标文件是否存在；若正文或 INDEX.md 中出现旧 `<mention-doc ...>` / `<cite ...>`，直接标记为 ERROR，因为那是飞书残留
   - **[D8 交叉引用缺失]** 检查同类型或关联主题的页面之间是否缺少双向引用
   - **[D9 缺失页面-补充]** 统计页面正文中高频提及但无独立页面的实体/概念名称
   - 元数据完整性：frontmatter 字段是否齐全、必须段落是否存在（标题按 [wiki-schema.md](../wiki-schema.md) 中各类型「等价」列做松匹配，如 `## 来源` ≡ `## 相关来源`）

5. **源文档过时检查（脚本辅助）**
   - **[D10 源文档更新]** 从步骤 4 读的所有 Source 类型页面中提取：
     - `原始来源` 中 `[[...]]` / `![[...]]` 的 raw 相对路径
     - `updated` 中的时间戳
     - raw 文件的类型：md → `md`；附件 → `file`
   - 构造 JSON 数组，调用检查脚本：
     ```bash
     echo '<JSON_ARRAY>' | bash <skill_base_dir>/scripts/check_staleness.sh
     ```
     输入格式: `[{"source_title":"...","raw_path":"...","raw_doc_type":"md","recorded_update":"YYYY-MM-DD HH:mm"}]`
   - 解析脚本输出（基于文件 mtime 对比）：
     - `stale` → D10 WARNING（展示源标题、记录时间、实际修改时间、时间差）
     - `missing` → 仅表示 raw 文件不存在，补充 D2 断链引用证据
     - `errors` 或脚本非 0 退出 → stale 检查失败，报告为独立检查错误并中止 D10 判断

   > D7 检查不同源文档之间的内容取代关系，D10 检查同一 raw 文档是否在 Source 页处理后被修改。

6. **内容级深度检查**（在步骤 4 已读的页面上进行）
   - **[D6 矛盾检测]** 对比不同页面中对同一实体/概念的描述，识别事实冲突
   - **[D7 过时声明]** 按时间排序源文档，检查早期页面中的论述是否已被新源取代

7. **核对检查清单**

   生成报告前，逐项核对 D1–D10 是否全部执行：
   - [ ] D1 空白页面
   - [ ] D2 断链引用
   - [ ] D3 未索引页面
   - [ ] D4 重复页面
   - [ ] D5 孤立页面
   - [ ] D6 矛盾检测
   - [ ] D7 过时声明
   - [ ] D8 交叉引用缺失
   - [ ] D9 缺失页面
   - [ ] D10 源文档更新

8. **生成报告**（按严重级别分组）
   - **ERROR**: D1 空白页面、D2 引用格式与断链、D3 未索引页面、缺失必须段落
   - **WARNING**: D4 重复页面、D5 孤立页面、D6 矛盾声明、D7 过时内容、D10 源文档更新
   - **INFO**: D8 交叉引用缺失
   - **SUGGESTION**: D9 缺失页面、建议探索的新问题、推荐寻找的新源

9. **用户确认后执行修复**（均通过 Read → 改写 → Write 回写）
   - 自动修复: 补充交叉引用、修复断链、将旧 `<mention-doc token="X"...>` 替换为 `[[X 路径]]`（文件附件替换为 `![[X 路径]]`）→ 精确改写相关段落
   - 需确认:
     - 补充空白页内容 → 追加缺失段落
     - 删除空白页 / 合并重复页 / 更新过时内容 / 重新摄入已更新的源文档（re-ingest）→ 整页重写或局部修订
     - 创建缺失页面 → 在对应 wiki/ 子目录用 Write 创建 `.md`
   - INDEX.md 注册表 / 配置的同步写回遵循 [wiki-schema.md](../wiki-schema.md)「索引操作规则」（整篇重写首选）

10. **更新 LOG.md**
