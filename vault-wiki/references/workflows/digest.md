# Digest — 目录聚合生成 wiki 页面

## 前置条件

- vault 根目录可访问（`$VAULT` 环境变量或回退）
- 用户提供源目录的 vault 相对路径（如 `13_资讯/经济`）
- 输出 wiki 页面在源目录平级：`源目录 + "wiki.md"`（如 `13_资讯/经济-wiki.md`）

## Step 0 — 自动去重（必须先行）

枚举叶子后，按以下规则识别重复组：

1. **基础名构建**：去掉 `_2` 后缀（如 `文章_2.md` → `文章.md`）+ 去掉 emoji 前缀
2. **同组判定**：基础名相同的文件为一组
3. **保留策略**：每组保留文件大小最大的，删除其余
4. **额外清理**：文件名含"副本"或仅空格差异（如 `A 又慢又贵 痛点` vs `A又慢又贵痛点`）也视为重复，直接删小文件
5. **结果**：得到去重后的干净叶子列表，再进入 Step 1

> 去重理由：Get笔记/剪藏等工具常产生 `_2`、`副本`、emoji 前缀等重复文件，不去重会导致 wiki 内容臃肿且引用混乱。

## Step 1 — 确认源目录 + 枚举叶子

1. 确认 `SOURCE_DIR` 存在且是目录
2. 运行 list_leaf_docs.sh 枚举叶子：
   ```bash
   SOURCE_DIR="13_资讯/经济" bash <skill_base_dir>/scripts/list_leaf_docs.sh
   ```
   输出：
   ```json
   {
     "files": [
       {"rel_path": "13_资讯/经济/文章A.md", "title": "文章A标题"}
     ],
     "errors": []
   }
   ```
3. 若 errors 非空，中止并报错
4. 展示去重后叶子数量，确认后继续

## Step 2 — 读取叶子正文

对每个文件：
- 读取 frontmatter（提取标题、日期、标签）
- 读取正文（提取核心观点、关键引用）
- 记录足够内容供 LLM 生成章节

## Step 3 — 生成 wiki 内容（LLM）

### 内容组织原则

**先通读，再按主题/维度划分章节**，不用固定模板：

- 识别叶子文档中的主题维度（如"宏观经济"、"技能生态"、"安全防护"）
- 每个维度一章，汇聚相关叶子的核心内容
- 跨文档的共识/分歧要显式标注
- **每个引用点必须用 `[[rel_path]]` 指向原始叶子**

### 必须包含的部分

1. **frontmatter**：`type: wiki-digest`、`created`、`updated`、`source_dir`
2. **目录导航**：每个章节的 anchor 链接
3. **各主题章节**：每个章节内用 `[[叶子路径]]` 引用原文
4. **参考原文**：页面末尾列出所有叶子 md 的 wikilink 列表（不含 leaves，参考原文段即完整列表）

## Step 4 — 增量判断

检查目标 wiki 页面是否已存在：

- **不存在**：直接生成完整 wiki，写入
- **存在**：
  1. 读取正文参考原文段的 wikilink 列表
  2. 与 Step 0 结果求差集 → 新增叶子
  3. 若无新增叶子 → 告知用户「已是最新」，中止
  4. 若有新增叶子 → 在末尾追加新章节，不重写已有章节

## Step 5 — 写入 wiki 页面

用 Write 工具写入 `源目录平级 + "wiki.md"`：
- 绝对路径：`$VAULT/13_资讯/经济-wiki.md`

## Step 6 — 回链到叶子 md

对每个叶子 md，在正文末尾追加/更新 backlink 段：

```markdown
---

## 关联 wiki

本文收录于 [[13_资讯/经济-wiki]]
```

- 若叶子 md 已有 `## 关联 wiki` 段，更新 wikilink 目标（不重复追加段落）
- 不要修改叶子 md 的已有正文内容

## Step 7 — 报告

向用户输出：
- wiki 页面路径（wikilink 格式）
- 去重后叶子数量
- 章节结构（标题列表）
- 双向链接状态
