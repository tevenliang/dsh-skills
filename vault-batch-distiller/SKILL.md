# Vault 批量蒸馏

## 做什么

把 vault 里某个一级目录下的所有二级研究主题，各生成一篇结构化的研究笔记。

- 输入：`steven_vault/{一级目录}/{二级目录}/` 下的 `.md` 源文件
- 输出：`steven_vault/llmwiki/{一级目录}/{二级目录名}-YYYY-MM-DD.md`
- 规则：只读源文件、提取标题层级+开头摘要避免爆上下文、双向链接 `[[文件名]]` 必须 0 死链、每篇带 🟢🟡🔴 证据等级

## 触发词

- "把 {目录} 下所有二级目录整理成笔记"
- "批量蒸馏 vault"
- "对 {一级目录} 做知识整合"
- "用 material-organizer 处理 vault"

## 执行流程

### 1. 扫描结构

用 Python 扫描 `steven_vault/{一级目录}/` 下的二级目录，输出：

```
{一级目录}/{二级目录}: X md
```

### 2. 分批策略

| 单目录 md 数 | 处理方式 |
|-------------|---------|
| ≤ 30 | 一次蒸馏 |
| 31–100 | 分 2–3 批，每批 ≤30，先生成子摘要，再综合 |
| > 100 | 先聚类/分片，再分批综合 |

多个一级目录可启动 **并行后台 agent**；同一一级目录下的二级目录顺序处理。

### 3. 提取结构化摘要

对每个 md 只提取：
- 文件名
- 标题层级（H1-H3，最多前 12 条）
- 正文开头摘要（非空非标题行，最多 18-20 条）

不读全文，避免上下文爆炸。

### 4. 生成分类蒸馏笔记

笔记结构必须包含：

```markdown
# {主题名}主题研究笔记

## 提炼总览
- 总文件数 / 总字符数 / 总标题数
- 核心共识（1-3 句）
- 关键分歧/张力

## Action Items
- 2-4 条可操作结论

## 分类蒸馏
### A. {分类名}
1. **[[文件名]]**：一句话核心观点
   - 来源：[[文件名]]
   - 证据：🟢/🟡/🔴
   - 原文要点：2-4 条 bullets

### B. ...

## 收件筐 / 偏离或空内容
- [[文件名]]：说明

## 跨主题洞察
## 矛盾与存疑
## 关键词索引
```

### 5. 双向链接校验（强制）

生成后用 `scripts/validate_links.py` 校验：每个 `[[文件名]]` 必须精确命中对应二级目录下的真实 md 文件名（去掉 `.md`，精确大小写、空格、全角符号）。

**必须 0 死链** 才算完成。

### 6. 进度与汇报

每个一级目录下创建 `.__progress.md`：

```markdown
- [YYYY-MM-DD HH:MM] 完成 {主题名}（X md）→ {输出文件名}
```

全部完成后生成或更新总索引：`llmwiki/!INDEX-YYYY-MM-DD.md`。

## 关键规则

1. **不改原文**：源文件只读，笔记只写到 `llmwiki/`
2. **0 死链**：所有 `[[文件名]]` 必须可跳转
3. **分片**：>30 md 必须分片
4. **证据等级**：每条核心观点标注 🟢 高 / 🟡 中 / 🔴 营销或待验证
5. **skip 目录**：产物目录（如 `WorkBuddy-知识框架`）、空目录、`.trash` 等

## 资源

- `scripts/extract_md.py`：批量提取标题层级+开头摘要
- `scripts/validate_links.py`：校验 wikilink 0 死链
- `references/prompt-template.md`：后台 agent 用的完整 prompt 模板
- `references/example-output.md`：示例输出片段

## 典型调用

```
用户：帮我把 steven_vault/21_ai 下所有二级目录蒸馏成研究笔记，输出到 llmwiki
```

执行：扫描 → 分批次启动后台 agent → 每目录提取+蒸馏+校验 → 写进度 → 生成索引 → present 结果。
